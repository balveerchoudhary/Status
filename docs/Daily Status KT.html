Daily Status

A mobile-first web page for logging the day's work once, then using it twice: post today's tasks to a Google Chat space, and download the month as the Timesheet Excel file.

OwnerBalveer Choudhary
Repogithub.com/balveerchoudhary/Status (private)
HostingGitHub Pages, branch main
StackPlain HTML + JavaScript, no build step

What it is

Each person types their tasks into the page during the day. The page keeps them in that person's browser. Two buttons turn the same entries into the two things the team needs every day.

JobButtonResult
Daily updateSend to ChatOne message in the team's Google Chat space: name, date, one bullet per task description. Hours and sprint are left out.
Monthly timesheet⬇ TimesheetAn .xlsx with Date, Task context, Task sub context, Description, Hours, one row per task, oldest first.

It exists to remove the double typing: the Chat update and the Gist.ly timesheet used to be written separately. Design goals were few taps on a phone, nothing to log in to, and nothing to host.

Architecture

There is no server of ours. GitHub Pages serves three static files; everything after that happens in the browser.

A task

{ id, date: "2026-10-13", ctx: "Sprint-154", sub: "AVID-50", desc: "...", hrs: 2,
  chat: true,            // false = stays in the Timesheet, never goes to Chat
  def: true, defId,      // only on tasks created from a daily default
  leave: true }          // only on the Leave entry

How the key flows work

Daily defaults

  1. When a weekday is used for the first time (the page opens on it, a task is added to it, or a task is copied to it), the page checks mat.
  2. If the date is not there, it adds one task per default that has add every weekday on, marks them def: true with the default's chat value, and records the date in mat.
  3. Changing a default later affects today and future days, not days already created.

Send to Chat

  1. Collect today's tasks that have a description and the Chat icon on.
  2. Build the text: *Name* — 13-Oct-2026, then one • description line each. Any @Full Name is converted to @username.
  3. Show it in the review dialog. The user may edit it; edits affect only this message.
  4. On Send, POST { "text": ... } to the webhook as text/plain with mode: 'no-cors'. This avoids a CORS preflight, which Chat would not answer.
  5. The browser hides the reply, so the page can only say "sent". Delivery is checked by looking in the space.

Timesheet download

  1. Take the tasks of the selected month, sorted by date then by list order. Days marked Leave without an entry get a "Leave" row.
  2. ExcelJS builds the workbook. Mentions become @username. If anyone was mentioned, a second sheet lists their id, name, email and UUID.
  3. On Chrome or Edge on a computer the first download asks where to save and remembers the file. After that the same file is overwritten, then read back and checked for size, and the message shows entries, size and time. If that is not possible, a normal download happens.

Sprint number

The number goes up by one every week on a chosen weekday. Settings holds one known point: the number that applies on the anchor date.

weekStart = last chosen weekday on or before the anchor date
number    = num + floor((date − weekStart) / 7 days)
default   = { prefix: "Sprint-", num: 153, day: 2 (Tue), anchor: "2026-10-06" }
check     : Tue 13-Oct-2026 → Sprint-154;  Mon 12-Oct-2026 → Sprint-153

Apply sprint settings re-labels every saved entry, because the sprint is always derived from the date.

@ mentions

  1. Typing @ at the start of a word shows matches from team.json by name or email.
  2. Picking one inserts @username (the part of the email before the @).
  3. Export and Chat recognise both @username and @Full Name, longest match first, and stop at a word boundary.

Run, deploy, set up

Run it on your machine

Serve the folder over http. Opening the file directly breaks loading team.json, so the @ picker would be empty.

cd Status
npx serve .

Deploy

Repo Settings → Pages → Deploy from a branch → main / root. Every push to main publishes in a minute or two. Pages for a private repository needs a paid GitHub plan.

First use, per person

  1. Open the page, scroll to Settings at the bottom.
  2. Enter your name and the Chat webhook URL, press Save settings.
  3. Optional: sprint name, number and weekday; your daily defaults.

To make a webhook: in the Chat space open Apps & integrations → Webhooks, add one and copy its URL.

Add a person to the @ list

WD_TOKEN=<token> node tools/add-person.js new.person --dry   # preview
WD_TOKEN=<token> node tools/add-person.js new.person         # write team.json

It calls Workdiary's groups_and_employees.json?query=<part before @> and keeps only the exact email match. The token is your logged-in session, copied from the authorization header of any Workdiary request in the browser DevTools Network tab. Commit and push team.json afterwards.

Security

The Chat webhook URL contains a secret token. Anyone who has it can post to the space. It is pre-filled as DEFAULT_HOOK in index.html, so it is visible to everyone who can read the repository or the published page. That is acceptable only while the repository stays private.
  • Keep the repository private. If it is ever shared more widely, remove DEFAULT_HOOK and have each person paste the URL in Settings. If the URL may have leaked, delete and re-create the webhook.
  • The Workdiary token used by add-person.js is a session credential. Read it from the environment only, never put it in a file, a commit or a chat. It expires with the session.
  • The page sends data only to the Chat webhook. It loads ExcelJS from cdnjs; pin and review the version when updating.
  • Data stays in the browser. A shared computer shares the data.

Limits and gotchas

  • Data is per browser and per address. The Pages site and localhost are separate. Clearing site data or using a private window loses it. Downloading the Timesheet is the only backup.
  • Chat delivery cannot be confirmed by the page (the no-cors trade-off). Chat also limits a space to about one message per second; the page sends one per press.
  • Updating the same Timesheet file works only in Chrome and Edge on a computer. Elsewhere each download is a new file, and the browser may add "(1)".
  • The file is rebuilt from the page's history each time. Changes made by hand in Excel are replaced. Excel does not reload a file changed behind its back, so close and reopen it to see the update.
  • Gist.ly import is manual. Upload the file on Gist.ly's page and pick a Group first, otherwise the rows are saved as drafts.
  • A single task is capped at 8.5 hours, and the page warns above 4 hours.
  • There are no automated tests in the repository.

Tried and removed

Direct import into Gist.ly. Not possible from a web page: Gist.ly's API answers browsers only from its own site, and the login is a cookie on its own domain. I built a bookmark-plus-pop-up bridge and a command-line uploader and tested them against a fake server, then removed both. A real fix needs Gist.ly's owners to allow our site or offer a token flow.

Also removed on request: a group picker in Settings, a Timesheet mention-format setting, and a Chat resend confirmation (replaced by the review dialog).
